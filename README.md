# NMIBC innervation

Analysis code for stromal tumor-associated nerves (STaNs) in high-risk non-muscle-invasive bladder cancer. The workflows cover nerve phenotyping, clinical associations, bulk RNA-seq, single-cell expression context and spatial measurements. Classifier development is maintained separately in [gotNeRve](https://github.com/cdeit/gotNeRve).

## Setup and inputs

Use the reference R environment and run commands from the repository root. The recorded downstream runs used R 4.3.3; spatial preprocessing requires a separate R 4.4.1/Linux environment. Package versions and validation limits are listed in [reproduction status](docs/REPRODUCIBILITY.md) and [spatial system requirements](docs/spatial/SYSTEM_REQUIREMENTS.md). Scripts do not install or upgrade packages.

Obtain the analysis inputs and place them at the paths in [data/README.md](data/README.md). Large images and study datasets are distributed separately. This code-only repository does not contain every required input.

Configuration files are grouped in `config/`:

- `config.R`: shared paths, non-spatial analysis settings and output directories.
- `spatial_config.R`: spatial statistical models and plotting settings.
- `spatial_measurement_config.R`: segmentation, distance and band-measurement parameters.

## Run analyses

For analysis-ready patient data and transcriptomic inputs:

```sh
Rscript --vanilla run_all.R 02 03 04 06
```

Each selected workflow runs in a separate R session. A failure stops the runner. Steps execute in the order supplied; dependencies are not downloaded or regenerated automatically. To run one workflow:

```sh
Rscript --vanilla scripts/04_run_DESeq2_GSEA.R
```

| Script | Input / purpose | Output root |
|---|---|---|
| `01_run_nerve_clustering.R` | Table S4 and clinical matching tables → nerve phenotyping and patient aggregation | `data/processed/`; `results/nerve_clusters/` |
| `02_run_clinical_analysis.R` | Patient RDS → clinical associations and heatmaps | `results/clinical/` |
| `03_run_subtype_analysis.R` | Patient RDS → subtype associations | `results/subtypes/` |
| `04_run_DESeq2_GSEA.R` | Table S1 and A/B counts → DESeq2, GSEA, NES and Jaccard plots | `results/bulk_RNAseq/` |
| `05_run_single_cell_analysis.R` | Annotated Chen object, bulk DEGs and prepared gene annotations → heatmaps | `results/single_cell/` |
| `06_run_nerve_cluster_analysis.R` | Patient RDS → cluster abundance, composition and Cox models | `results/nerve_clusters/` |
| `07_compute_spatial_data.R` | Segmentation TIFFs → masks, distances and band measurements | `data/processed/` |
| `08_run_spatial_analysis.R` | Archived measurements, patient RDS and S4F mapping → spatial models and plots | `results/spatial/` |

Statistical tables and figures go in each workflow's `tables/` and `figures/` subdirectories. Intermediate datasets used by downstream analyses stay in `data/processed/`.

Script 04 supplies DEGs for 05. Script 08 can use archived measurements without running 07. Steps 01 and 07 are explicit upstream regeneration steps, not prerequisites when the corresponding processed inputs are already available. Script 01 writes its configured patient RDS, so retain the reference input before regenerating it.

Spatial preprocessing is skipped when `cfg$use_precomputed_spatial` is TRUE (the default). For regeneration, follow the [spatial instructions](docs/spatial/README.md); the pipeline prepares masks, computes measurements, validates them against reference tables and saves validated CSVs for downstream use. Validation does not upload anything online.

## Analysis populations

Clinical and outcome analyses require adequate BCG. Bulk DESeq2/GSEA compares STaN abundance rather than treatment outcome and applies the minimum stromal-area threshold without an adequate-BCG restriction. The checked input contains 97 RNA-matched patients, yielding 33 STaN-low and 33 STaN-high samples using within-cohort quantiles.

Upstream phenotyping and spatial measurement generation retain broader populations. Published image inclusion flags are applied downstream. S4F supplies image-to-patient mapping; S1 supplies bulk patient data. Clinical fields and stored STaN strata absent from S1 remain in the analysis-ready RDS. See [supplementary-table inputs](docs/SUPPLEMENTARY_TABLE_INPUTS.md).

Chen single-cell data provide cellular context for bulk STaN-associated genes. Chen STaN status is unknown. Heatmaps read prepared gene annotations from `nerve_communication_genes_ann.rds`; see [single-cell instructions](docs/SINGLE_CELL_HEATMAPS.md).

## Figure code

Clinical Figure 2A and Figure S10C heatmaps are generated by 02; the Figure 3A subtype heatmap by 03. Bulk volcano, NES and Jaccard plots are generated by 04; single-cell heatmaps by 05; cluster abundance/composition and Cox plots by 06; spatial model plots by 08. Output basenames retain the existing figure labels. Final manuscript panel numbering should be checked against those filenames.

## Reproduction status

Several downstream workflows have completed on the reference inputs. Full end-to-end reproduction is not yet established: upstream matching inputs, a complete environment record, single-cell preprocessing validation, the annotated single-cell inputs and the original spatial distribution palette remain necessary. Optional imaging-survival settings are not configured. The code reports these limits instead of selecting alternative methods. See [workflow-specific requirements and validation](docs/REPRODUCIBILITY.md).
